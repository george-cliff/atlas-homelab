# Atlas roadmap

> [!WARNING]
> **Transparency:** this document was generated by AI and will be replaced with a human-written version soon.

This is a public, non-operational summary of where Atlas may develop next. Atlas's private canonical roadmap and current-state records remain authoritative. An item here is not approval, a commitment, or permission to change the live server.

## Status key

- **Current:** active documentation, validation, or maintenance around an implemented system.
- **Planned:** an accepted direction that still needs its own design, checks, or approval before implementation.
- **Idea:** worth investigating, but its scope and value are not yet settled.

## Current

- [ ] **Complete cross-machine development validation.** Verify the private Git workflow across Atlas, Pegasus, and Athena, including a recovery exercise for a backed-up repository.
- [ ] **Finish the public documentation set.** Review the hardware, services, storage, architecture, development, and roadmap pages and replace them with human-written versions.
- [ ] **Continue recovery verification.** Observe scheduled backup results, repeat representative restores, and retain the distinction between component tests and a complete bare-metal rebuild.
- [ ] **Plan the next storage step.** Confirm capacity needs, case constraints, disk-health expectations, and how new data changes off-site backup cost and coverage.
- [ ] **Reconcile workstation configuration.** Prepare reproducible Fedora and Windows tooling and dotfiles before later rebuilds of Athena or Pegasus.
- [ ] **Finish documenting recently added utilities.** Verify the persistence, backup, restart, and access behaviour of Mealie, Bar Assistant, and Cookdex before presenting them as established services.

## Planned

- [ ] **Expand storage capacity.** Add drive capacity and a more suitable case when the current constraints justify it, then review redundancy and backup policy.
- [ ] **Build the wider private documentation system.** Develop a searchable documentation site for Atlas and the other devices without exposing private operational records.
- [ ] **Complete the workstation rebuilds.** Reinstall Athena and the Pegasus dual-boot environment only after required data, settings, credentials, and recovery paths have been verified.

## Ideas to investigate

- [ ] **Historical metrics with Prometheus and Grafana.** Determine whether they add useful host, container, and storage history alongside existing availability checks.
- [ ] **Atlas Git Manager.** Start with read-only repository and diff review, then consider safe preparation of publication branches and optional GitHub integration.
- [ ] **Minutes productivity application.** Explore a self-hosted task, project, reminder, and calendar system with carefully bounded GitHub integration.
- [ ] **Read-only Atlas caretaker.** Investigate health summaries, log review, maintenance suggestions, and improvement recommendations; autonomous repair would require a separate design.
- [ ] **Custom homelab dashboard.** Consider combining navigation, documentation, service information, and selected monitoring without duplicating specialist tools.
- [ ] **Broader project review.** Inventory older work across Atlas, Pegasus, and Athena to decide what should be maintained, documented, published, or archived.

## Deliberately outside this public roadmap

- Private addresses, ports, schedules, credentials, access-control configuration, and production recovery commands.
- Exact maintenance tasks that belong in the private current-state record.
- Purchases, deployments, publication, destructive operations, or external access that have not received their own approval.
- Speculative features presented as if they were committed deliverables.
